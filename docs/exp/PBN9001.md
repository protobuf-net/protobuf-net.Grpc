`[ProtoGrpc]` and `[ProtoService]` generate gRPC client proxies and server bindings at **compile
time**, so that protobuf-net.Grpc does not have to build them by reflection and ref-emit at runtime.
That is what makes a code-first gRPC service work under **native AOT** and trimming.

The feature is in preview, and the shape may still change:

1. The attributes and their properties may be renamed, moved, or gain/lose members.
2. The generated API surface — the `CreateClient` dispatch, the generated `Add{YourType}()`
   registration extension — may change shape.
3. They currently live in protobuf-net.Grpc; they may move, as protobuf-net's `[ProtoModel]` did.

None of that affects the *wire* format, which is ordinary protobuf either way — a service built this
way interoperates with anything, and you can go back to the runtime path by deleting the model type.

If you acknowledge this, you can suppress this warning by adding the following to your `csproj` file:

```xml
<NoWarn>$(NoWarn);PBN9001</NoWarn>
```

or more granularly / locally in C#:

``` c#
#pragma warning disable PBN9001
```

Note that **the same id covers protobuf-net's `[ProtoModel]`**, which is the serializer half of the
same story — you will normally want both, and one entry opts into both.

See [Native AOT and trimming](../aot) for what to do with it, and
[the protobuf-net AOT documentation](https://docs.protobuf-net.dev/aot) for the serializer half.
